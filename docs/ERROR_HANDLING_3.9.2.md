# Олешка — безопасные ответы при неполадках Gemini, Worker 3.9.2

**Состояние на 3 ноября 2026:** GitHub Pages обновлён; серверный Worker 3.9.2
подготовлен на основе точного пользовательского архива версии 3.9.1,
**но не развёрнут автоматически**. Релизный архив с полным исходником
предоставлен владельцу отдельно; в ветке `main` лежит исправленный UI,
автотесты и данная документация.

## Подтверждённая база
Файл исходного Worker: `oleshka-worker-v3.9.1-date-scope-fix.js`.
SHA-256: `eddb18c989a055ce08199050b2dcc6f80f95963a5ffd602d725d0e74a5e34ea5`.
В оригинальном релизе: 221916 байт.

## Новый серверный файл
`oleshka-worker-v3.9.2-friendly-errors.js`.
SHA-256: `fd4c45d4b54b7bc2b9ffa0310325c916571b2980aee8a85abb1d7c71789a97fc`.

**Изменяется только обработка ошибок и релизная версия:**
- сообщения при `provider_quota`, `provider_busy`, `service_unavailable`,
  `response_blocked` выводятся словами Олешки, не строкой Gemini/Cloudflare;
- структурированный статус 429 Gemini + `RESOURCE_EXHAUSTED` /
  `QuotaFailure` помогает определить ограничение провайдера;
- ограниченный переход между модельными резервами остаётся;
- короткая, best-effort пауза после 429 в текущем Worker isolate, не
  глобальное ограничение и не прогноз времени сброса Gemini;
- исправлен месячный ответ Олешки: теперь корректно предлагает вернуться
  в начале следующего месяца;
- дневник, D1, Vectorize, календарная хронология из 3.9.1,
  административные страницы, API, секреты и Cron не изменялись.

## Исправления интерфейса уже в GitHub
Публичный сайт отныне выводит слова Олешки при `503/422`, а также при
невалидном JSON, HTML-странице Cloudflare и сетевом обрыве.
Вопрос остаётся для повторной отправки, ошибка не превращается
в сообщение модели при следующем запросе. Отдельная роль `notice`
доступна только локально для отображения. Поле ввода само разблокируется
при наступлении достоверного срока `retryAt` после внутреннего лимита.

GitHub Actions `Oleshka UI safety checks` выполняет независимые проверки
синтаксиса скриптов и правил обработки ошибок/истории.
Серверный файл 3.9.2 проверен локально Node.js: syntax check и 7/7
тестов с имитацией Gemini (429, 503 HTML, смена моделей, SAFETY, 401).
Ни один тест не расходует деньги/квоту Gemini.

## Как завершить внедрение
Cloudflare Dashboard → Workers & Pages → `oleshka-chat-api` → Edit code.
Заменить код содержимым `oleshka-worker-v3.9.2-friendly-errors.js`
из выданного приватного архива, затем нажать Deploy.
Проверить `https://oleshka-chat-api.boysinger2008.workers.dev/`
и значение `version: "3.9.2"`.

Для отката есть файл `BACKUP-oleshka-worker-v3.9.1.js` в том же архиве.
**Никаких новых SQL, bindings, secrets или изменений GitHub Pages не требуется.**

## Проверка вручную
После установки проверить обычное общение и хронологию («вчера»,
«позавчера», «23 октября») без изменения фактов. Для контролируемой
проверки не исчерпывать настоящую квоту: сравнивать поведение с локальными
mock-тестами. При реальном сбое, если Worker вернул HTML/500,
интерфейс обязан сохранить вопрос и показать фразу Олешки.

До фактического deploy серверная классификация ошибок 3.9.2
**не считается включённой**. Без развёртывания обновлённый интерфейс
всё равно скрывает технические ошибки, но не имеет всех преимуществ
новой серверной классификации и временных пауз.
